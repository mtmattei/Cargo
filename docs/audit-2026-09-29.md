# UI Audit — 2026-09-29

Scope: all 8 sections + scanner overlay, `net10.0-desktop` Debug build (0 errors, 5 warnings).
Evidence: live capture matched `shots/` baseline; code findings verified file:line.
Direction under consideration: soft isometric pastel harbour (Kyoto Station platform-map reference), possibly orbitable.

## Anti-Patterns Verdict

**Partial fail.** Not generic slop — the type pairing (Bricolage / Archivo / Plex Mono), warm paper neutrals and single card style are real decisions. But the app fails on **coherence**, and carries several tells:

- **Four rendering languages on one screen:** photoreal aerial terminal + photoreal ship sprites, flat vector UI (yard, security plan, berth boxes), glossy 3D container renders (Containers), and a teal-on-dark wireframe (scanner).
- **Dark bands cutting light pages:** dark nav, dark teal harbour strip (Overview/Vessels/Security), dark crew-chat card (Fleet), full dark scanner.
- **Hero-metric row** on Overview (`3 alongside · 2 inbound · 167 moves/h …`).
- **Monospace as "technical" shorthand:** mono eyebrows on every page, mono nav indices `01–08`.
- **Icon-above-every-stat** cards on the Vessels side profile.
- **Cyan/teal-on-near-black** scanner = the AI dark palette.
- Grid-paper texture behind every page.

Top issues:
1. `Tokens.Color()` drops brush opacity → every code-set hairline renders solid ink (heavy black outlines everywhere).
2. Visual incoherence — four art styles; the harbour is photoreal while everything around it is flat.
3. Label collisions/clipping on Overview, Vessels, Fleet, Security.
4. No keyboard/screen-reader path for berth assignment, bay/yard selection; zero `AutomationProperties` in the app.
5. Full element rebuilds on drag/tick (BerthMap ~210 elements per PointerMoved; YardMap ~760 per yard move).

## Patterns & Systemic Issues

- Rebuild-on-change is the default in scene controls (BerthMap, YardMap, RiverMap, PortStage, Scanner); only hover paths use repaint.
- Status colours double as text colours without ink variants → systematic contrast failures on light and water surfaces.
- Scene text lives inside `SceneHost` scaling → every scene has the tiny-label problem.
- Inline typography/spacing instead of the 13 existing text styles.

## Positive Findings

- One Card style, no nested cards, one soft shadow, no accent-stripe borders.
- Tokens grouped semantically; warm-tinted neutrals, cool-tinted ink.
- Brush/geometry/bitmap caching; `Live.cs` defers work while unloaded; hidden-section timers genuinely stop.
- Motion via `TranslateTransform` (yard RTGs, crane scene) instead of rebuilds.
- Native `Slider` scrubber; custom Buttons keep system focus visuals.
- `ContainerScanner` already contains working camera math (rotate + perspective + painter's sort) — the seed of an orbitable harbour.

## Recommendations by Priority

1. **Immediate:** C1 hairline opacity bug; C3/C4 overlaps; H11 pin Light theme.
2. **Short-term:** Decide scene language (C2) and spec it; contrast tokens (H5–H7); label collisions (H9).
3. **Medium-term:** Perf rebuild→repaint (H1–H4, M1–M3); a11y/keyboard (C5, C6, M4, M7); type/spacing scale (H10).
4. **Long-term:** Responsive shell for phone/wasm (C7); reduced motion (M6).

## 3D / isometric harbour readiness (from perf review)

Helps: `Skia` UnoFeature already on (SKCanvasElement available); `SceneHost` single design space → `canvas.Scale`; `PortState` signals map to rebuild-model / invalidate / patch; scanner projection math.
Blocks: pre-rendered sprites can't orbit; per-element hit-testing/tooltips need Skia hit-testing via inverse projection; ShellPage callouts need world→screen projection per frame; automation names on hull Buttons would need a replacement (AutomationPeer on the canvas).
